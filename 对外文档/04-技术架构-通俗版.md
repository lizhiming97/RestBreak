# 04 技术架构（通俗版）

这一篇用大白话讲歇一会是怎么搭起来的。不需要懂编程，把它想成一家小公司就好。

## 整体：一家分工明确的小公司

```
┌──────────────────────── 歇一会.app ────────────────────────┐
│                                                            │
│   感知部门（Services）        大脑（Engine）                │
│   麦克风在不在用？            现在该不该休息？              │
│   是不是全屏？        ──▶     该推迟还是提前？    ──┐      │
│   日历上有什么？              统计今天休息了几次    │      │
│   键盘鼠标闲置多久？                                │      │
│                                                     ▼      │
│                          总指挥（App）                      │
│                          每秒问一次大脑，把结论交给前台     │
│                                                     │      │
│                                                     ▼      │
│   前台（UI）                                               │
│   菜单栏倒计时 · 休息遮罩 · 设置窗口 · 统计图              │
│   截图框选 · 标注工具栏 · 贴图 · 灵动岛                    │
│                                                            │
│   ┌───────────────────────────────────────────────┐        │
│   │ restbreak-mcp（包里的小程序，负责和 AI 对话）  │        │
│   └───────────────────────────────────────────────┘        │
└────────────────────────────────────────────────────────────┘
```

代码目录也是按这个分的：

| 目录 | 角色 | 通俗解释 |
|---|---|---|
| `Engine/` | 大脑 | 只管「算」：调度规则、统计、截图几何、标注模型、翻译签名。不碰任何界面和系统接口，所以最好测试 |
| `Services/` | 感知部门 | 和系统打交道：读麦克风状态、窗口列表、日历、钉钉、快捷键、截屏、通知 |
| `App/` | 总指挥 | 把感知到的信息喂给大脑，把大脑的结论交给前台 |
| `UI/` | 前台 | 所有你看得到的东西 |
| `Shared/` | 公用资料室 | 主程序和小程序都要用的东西：提醒的数据格式、存取、排期规则 |
| `RestBreakMCP/` | 对外联络员 | 一个很小的命令行程序，AI 助手通过它来读写提醒 |

## 休息调度：一个每秒问一次的「大脑」

调度的核心是一个叫 `BreakScheduler` 的模块。总指挥每秒钟问它一次：

> 「现在是 14:32:05，键盘鼠标闲置了 3 秒，没有睡眠，麦克风在用，没有全屏，前台不是指定 App，日历上 15:00 有个会。我该干什么？」

大脑回答：

> 「长休息本来 14:32 到期，但你在开会，先等着。会议结束 60 秒后再开始。」

大脑自己记着几件事：现在是「工作中」「离开了」「休息中」还是「暂停中」，每种休息下次什么时候到、已经推迟了几次。

这样设计的好处是：**大脑不知道时间是真的还是假的**。测试时可以喂给它「假时间」，一秒一秒地快进，几秒钟就跑完 20 个工作日。

## 「不打扰」的判断顺序

当一次休息到期时，大脑按这个顺序检查：

```
到期了
 ├─ 在开会？        → 等散会 + 60 秒
 ├─ 日历上有日程？  → 等日程结束
 ├─ 全屏或指定 App？ → 先等，累计最多 30 分钟
 └─ 都没有          → 开始休息
```

另外还有一条「提前」的规则：如果马上要开会，而休息也快到了，就把休息提前到会前。

## 截图：先定格，再加工

```
按快捷键
   │
   ▼
所有屏幕同时拍下来（ScreenCaptureKit）
   │
   ▼
在定格的画面上框选（每块屏幕一个最顶层窗口）
   │      ├─ 自动识别窗口和菜单栏图标
   │      └─ 放大镜精确取点、取色
   ▼
在选区里标注（8 种工具，可撤销）
   │
   ▼
出口：复制 / 保存 / 贴到屏幕上 / 提取文字 / 翻译
```

几个关键设计：
- **一份绘制代码**：屏幕上显示的标注和导出的图片用同一份代码画，保证所见即所得。
- **识字在本机**：用系统自带的 Vision，不联网，两行中英文大约 0.8 秒。
- **翻译走腾讯云**：系统自带的翻译要下载很大的语言包，在线接口 0.2～0.5 秒就够了。密钥存在系统钥匙串里。

## AI 派提醒：三方共享一个文件

```
我 ──聊天──▶ Claude Code / Codex / Claude Desktop
                 │ 启动包里的小程序，用标准输入输出对话（MCP 协议）
                 ▼
          restbreak-mcp 小程序
                 │ 加锁 → 读 → 改 → 原子写入 → 广播「提醒变了」
                 ▼
     共享文件夹（App Group）/ Reminders/store.json
                 ▲
                 │ 收到广播，重新读取、重新排期
          歇一会主程序
           ├─ 到点 → 刘海灵动岛
           └─ 兜底 → 系统定时通知（晚 90 秒，App 在运行时会撤掉）
```

AI 能用的工具一共 5 个：看概况、新建、列出、修改、删除提醒（列出时能看到每条提醒的完成记录）。为了防止 AI 失控，设了几道闸：

| 限制 | 数值 |
|---|---|
| 最多有效提醒 | 100 条 |
| 重复提醒的最短间隔 | 15 分钟 |
| 每个 AI 客户端每小时最多新建 | 20 条 |
| 最远往后排 | 400 天 |

提醒的「什么时候响」只由 App 里写死的规则决定：

- 晚了 5 分钟以内，算准时；
- 晚了 5 分钟到 12 小时（比如电脑睡着了），记为「错过」，汇总成一条通知告诉我；
- 超过 12 小时，只记录，不打扰；
- 重要提醒没处理，每 10 分钟再提醒一次，最多 3 次；
- 遇到休息中、开会、全屏，最多等 30 分钟再弹。

这些规则也有自己的模拟测试：用固定种子模拟 30 天，每 5 分钟处理一次，中间随机合盖几小时、随机处理或不处理强提醒，检查不会漏响、不会连响。

## 设计原则

做这个项目的过程中，慢慢形成了几条原则：

1. **能用系统的就不用第三方。** 主程序一个第三方库都没有。截图、识字、日历、图表都用苹果自带的框架。唯一的第三方依赖是官方的 MCP SDK，而且只给小程序用。
2. **从第一天就开沙盒。** 为上架 App Store 做准备，只申请需要的权限。很多功能（会议检测、全屏检测、全局快捷键）都特意选了不需要额外权限的做法，并逐一实测过。
3. **数据不出本机。** 休息统计、提醒都存在本机。App 不接任何大模型，没有 API Key。
4. **「算」和「显示」分开。** 所有规则放在不碰界面的模块里，用大量自动化测试守住。
5. **不确定的事先验证。** 大功能动手前先做「第 0 步」，把不确定的技术点逐一实测，再写设计。
6. **克制。** 不常用的设置不放，用不上的功能删掉，每个设置分段一屏放下。

## 技术清单

| 类别 | 用到的 |
|---|---|
| 语言 | Swift 6 |
| 界面 | SwiftUI + AppKit（菜单栏、无边框窗口、刘海窗口） |

| AI 接入 | MCP（Model Context Protocol）Swift SDK，stdio 传输 |
| 测试 | Swift Testing，237 个测试，含两个长时间模拟 |
