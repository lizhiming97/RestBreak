# 歇一会：各功能的实现细节与规则

从 `CLAUDE.md` 挪出来的各阶段细节（2026-10-26 整理时已按代码修正过时内容）。改某个功能前先读对应一节；改完同步更新这里。

## 第一阶段 MVP 范围
1. 菜单栏图标 + 距下次休息的倒计时（显示 "32分"，不到 1 分钟时显示 "45秒"，避免每秒跳动）。
2. 两种内置休息，各自独立计时、有优先级：
   - 长休息：每 60 分钟，休 5 分钟，推迟 5 分钟，优先级 0（最高）
   - 微休息：每 20 分钟，休 20 秒（20-20-20 护眼法则），推迟 2 分钟，优先级 1
3. 全屏休息遮罩：每个 `NSScreen` 一个无边框窗口，`level = .screenSaver`，`collectionBehavior = [.canJoinAllSpaces, .fullScreenAuxiliary, .stationary, .ignoresCycle]`，窗口子类重写 `canBecomeKey` 返回 true。背景用 `NSVisualEffectView`（behindWindow 模糊）加深色蒙层，内容有：休息名称、中文休息建议、圆环倒计时、「推迟 N 分钟」「跳过」按钮。淡入淡出。休息结束后重新激活之前的前台 App。休息期间 `NSApp.presentationOptions = [.hideDock, .disableProcessSwitching, .disableHideApplication]` 锁住 ⌘Tab 和切桌面空间（2026-10-26 用户发现休息时能划到别的全屏空间把遮罩甩掉），结束时恢复；设置窗口开着（App 临时是 `.regular`）时，休息开始先切回 `.accessory` 再建遮罩（普通 App 的窗口进不了别的 App 的全屏空间），结束后设置窗口还开着才切回。
4. 推迟 / 跳过，每次休息最多推迟次数可设（默认 2）；严格模式下隐藏这两个按钮。
5. 自然休息：用 `CGEventSource.secondsSinceLastEventType(.combinedSessionState, eventType:)` 检测闲置（`kCGAnyInputEventType` = `CGEventType(rawValue: ~0)`，拿不到时退回取多个事件类型的最小值）。闲置超过阈值（默认 5 分钟）视为离开。
6. 睡眠/锁屏：`NSWorkspace` 的 willSleep/didWake；`DistributedNotificationCenter` 的 `com.apple.screenIsLocked` / `com.apple.screenIsUnlocked`。分别记录"已睡眠""已锁屏"，两者都解除才算回来。
7. 菜单：下次休息信息、现在开始微/长休息、暂停（30 分钟 / 1 小时 / 2 小时 / 到明早 / 直到手动恢复）、恢复、重置计时、设置…、退出。（开机自动启动只放在设置窗口里，菜单不放，2026-10-20 用户要求）2026-10-26 用户要求提高信息密度：「现在开始微/长休息」合进倒计时行——每种休息一行「微休息　16:35（18 分钟后）」，右侧灰色「立即开始」（`StatusBarController.rowTitle`，右对齐制表位，位置按最长那行算——`tabLocation`，写死 300 会把菜单撑宽），点这一行就开始；状态说明（开会、日程、推迟、暂停、离开）只在有情况时显示一行灰字。「接下来的提醒」只在 24 小时内有提醒时显示，最多 2 行、点了打开「提醒」页，不要标题和「全部提醒…」。
8. 设置窗口（自己管理 `NSWindow` + `NSHostingController`，不用 SwiftUI `Settings` 场景，因为菜单栏应用里不好唤出）：两种休息的启用/间隔/时长/推迟时长、离开阈值、最多推迟次数、严格模式、菜单栏显示倒计时、开机启动（`SMAppService.mainApp`）、恢复默认。设置存为 JSON 放在 UserDefaults。休息结束提示音已按用户要求删除（2026-10-23），不要再加回。
9. 中文休息建议库：微休息（护眼、呼吸、坐姿）和长休息（起身走动、喝水、拉伸）两类，各 15 条左右，随机选且不连续重复。

## 调度引擎设计（核心逻辑，放在只依赖 Foundation 的 struct 里，方便单元测试）
- 状态：`running` / `away(since:)` / `onBreak(session)` / `paused(until: Date?)`。
- 每个休息存 `dueDate` 和 `postponeCount`。外层（@MainActor 的 `BreakCoordinator`）按 `nextTick(now:)` 给出的时刻调用 `tick(...)`（见「性能」），拿回事件（休息开始 / 结束 / 检测到自然休息 / 暂停结束）。
- 到期选择：在已到期的休息里取优先级最高的。如果更高优先级的休息在 5 分钟内也要到期，就自动跳过这个低优先级休息（dueDate = now + interval）。
- 开始一个高优先级休息时，把所有低优先级休息重置为 now + 各自间隔（防止推迟长休息后微休息立刻弹出）；高优先级休息完成后，再重置一次低优先级休息。
- 推迟：dueDate = now + 推迟时长，postponeCount + 1。跳过或完成：dueDate = now + 间隔，postponeCount 清零。
- 离开（闲置或睡眠锁屏）结束时：离开时长 ≥ 某休息的时长 → 该休息算已完成并重置；否则把它的 dueDate 往后顺延离开时长。
- 暂停结束或手动恢复时，所有休息都从现在重新计时。修改某个休息的间隔或启用状态时，只重置该休息。
- 休息中途睡眠：不特别处理，醒来后的 tick 发现已过 endsAt 就按完成处理。

## 其他规则（2026-10-20 代码审查后补充）
- 严格模式下休息中 `pause` 无效（防止用暂停快捷键绕过严格模式）。
- 暂停中手动开始的休息（菜单或快捷键），结束后回到原来的暂停状态（`stateAfterBreak`）。
- 设置滑条拖动时只改草稿值，松手（或按一次方向键）才写进设置，避免每经过一格都重置倒计时。
- 录快捷键时设置窗口失去焦点（关闭、切 App）自动结束录制、恢复快捷键注册。
- `RestBreakTests/DaySimulationTests.swift` 用固定种子逐秒模拟 20 个 8 小时工作日检查规则不变量；改调度规则后必须跑通。

## 第二阶段：会议检测（已完成）
- 「在开会」= 任意输入设备 `kAudioDevicePropertyDeviceIsRunningSomewhere` 为真（`MicrophoneWatcher` 用 CoreAudio 属性监听，不轮询；只读状态，沙盒内可用，不需要麦克风权限，已实测）。
- 引擎 `tick(now:idleSeconds:systemAway:inMeeting:)`；`isInMeeting` 含会后 60 秒缓冲期（`meetingGracePeriod`），防止静音时麦克风短暂关闭被误判。
- 开会中：到期的休息不弹，会议结束 + 缓冲期后再弹；闲置不算离开（听会时不碰键盘不等于在休息）；睡眠/锁屏仍算离开。
- 休息中麦克风从关变开（来电话/会议）：立即结束休息（`BreakEndReason.meetingStarted`），dueDate = now、不计推迟次数，会后补上。开着麦克风时手动开始的休息不打断。
- 设置项 `postponeDuringMeetings`（默认开）。菜单栏开会时图标为 `mic.fill`，休息已到期在等会议结束时显示「会后」。

## 第二阶段：休息前提前通知（2026-10-26 已删除）
- 用户不需要「休息前提前通知」，连同设置项（`notifyBeforeBreak` / `notifyLeadTime`）、`BreakNotifier`、引擎的 `.breakUpcoming` 事件和「通知上推迟」都删了，不要再加回。保留 `skipUpcoming`（快捷键「跳过下一次休息」在用）。

## 第二阶段：全屏检测（已完成）
- `FullscreenMonitor`（判断）+ `FullscreenWatcher`（只在切 App、切桌面空间、屏幕变化时重算，见「性能」）：前台 App（排除自己）有 layer 0 的窗口尺寸等于某块屏幕尺寸即为全屏；刘海屏上全屏窗口高度要减去 `safeAreaInsets.top`，两种尺寸都算。用 `CGWindowListCopyWindowInfo` 只读大小和 PID，沙盒内可用、不需要录屏权限（已实测）。
- 引擎 `tick(...fullscreen:)`：有休息到期且全屏 → 先不弹，累计推迟满 `maxDeferral`（默认 30 分钟，设置 5～60）照样弹，退出全屏立即弹。推迟时长是**累计**的（`deferredFor`，两次推迟 tick 间隔超过 2 秒的部分不算），所以中途开会、离开的时间不计入。开会优先于全屏。
- 推迟满上限时直接开始 `nextBreak()` 那个休息，不再套用「高优先级 5 分钟内到期就跳过低优先级」的规则。
- 用户主动推迟过的休息（`postponeCount > 0`）按推迟时长准时回来，不再因全屏/指定 App 重新推迟。
- 开会或全屏期间不碰键盘鼠标不算闲置：引擎记 `lastWatchingAt`，闲置 = min(真实闲置, now - lastWatchingAt)，散会/退出全屏后不会把整段追溯成离开。
- 菜单栏全屏时图标为 `arrow.up.left.and.arrow.down.right`，推迟中倒计时显示距推迟上限的时间。

## 第二阶段：指定 App 规则（已完成）

## 第二阶段：全局快捷键（已完成）

## 第三阶段：日历排程（已完成）
- 设置 `followCalendar`（默认关）+ `calendarIDs`（用户勾选的日历；第一次打开时默认勾选除生日、订阅日历外的所有日历）。沙盒权限 `com.apple.security.personal-information.calendars`，说明文字 `INFOPLIST_KEY_NSCalendarsFullAccessUsageDescription`，用 `requestFullAccessToEvents`（macOS 14）。
- `CalendarService`：只读勾选日历里 [now-1h, now+12h] 的日程，排除全天、「空闲」、已取消、自己已拒绝的；10 分钟或日历变化（`EKEventStoreChanged`）时重读；不开日历功能就不建 `EKEventStore`。
- 引擎 `tick(...calendarEvents: [DateInterval])`：日程进行中到期的休息不弹，日程结束后弹（日程中闲置照常算离开——去开线下会算自然休息；日程时间不计入全屏推迟）。
- 日程前提前：下一次休息的到期时间落在 (日程开始 - 时长 - 1 分钟, 日程开始 + 15 分钟] 内 → 提前到 max(日程开始 - 时长 - 1 分钟, 到期 - 15 分钟) 开始，前提是休息能在日程前结束；全屏/指定 App 推迟时不提前。
- `nextBreakStart(now:)` 给出考虑日程后的实际开始时间，菜单栏倒计时和侧边栏状态都用它。菜单栏日程中图标为 `calendar`。

## 第三阶段：休息统计（已完成）
- `StatsRecorder`（Engine，只依赖 Foundation）按天汇总 `DayStats`：完成 / 跳过 / 推迟次数、离开电脑算作休息的次数、累计休息时长（完成的休息 + 离开时长）、最长连续工作。被暂停或会议打断的休息不计。完成率 = 完成 /（完成 + 跳过）。
- 连续工作：只在 `.running` 时累计，完成一次休息或离开电脑（naturalBreakDetected 且有休息算完成）后重新算；跳过/推迟不算休息；暂停、离开、休息中中断；两次 tick 间隔超过 15 分钟重新算（tick 按需醒，见「性能」）。
- 保存为 JSON 文件（`StatsStore`，App 沙盒的 Application Support/RestBreak/stats.json），只保留 90 天；有休息事件、睡眠/锁屏、退出时立即存，否则有变化时最多 15 分钟存一次。没用 SwiftData（数据量小，JSON 更简单、好测试）。
- 设置侧边栏第一项「统计」页（`UI/StatsPage.swift`，Swift Charts）：今日概览、7/30 天堆叠柱状图、每天最长连续工作柱状图（超过 60 分钟标橙、画参考线）。菜单顶部「今天已休息 N 次，完成率 x%」点击直接打开统计页；「设置…」打开「休息安排」。

## 第三阶段：钉钉日历（已完成）
- 「按日历安排休息」下选 `calendarSource`：`.mac`（EventKit）或 `.dingtalk`（只做这两种，不做合并）。日程中不弹 / 日程前提前的逻辑共用。
- 钉钉官方「钉钉日历」MCP：`https://mcp-gw.dingtalk.com/oauth/server/calendar`（Streamable HTTP，未登录返回 401 + `resource_metadata`）。授权服务器 `https://mcp-gw2.dingtalk.com`：支持动态注册（`/oauth/register`）、授权码 + PKCE S256、`client_secret_post`、refresh_token，scope `user`。回调地址只允许 https 或本机 http，所以用 `http://127.0.0.1:38127/callback`（`NWListener` 临时监听）。access_token 有效期约 6900 秒。服务端不返回 Mcp-Session-Id，返回普通 JSON。
- `list_calendar_events` 参数（2026-10-21 实测）：`startTime` / `endTime` 为毫秒时间戳（只返回开始时间 >= startTime 的日程，所以查询起点取 now-8h，终点 now+12h），`limit`（最大 100），`calendarId` 默认 `primary`，`cursor` 分页。返回 `{"result":{"hasMore","events":[{summary,start:{date,dateTime,timeZone},end,isAllDay,status,freeBusy,attendees:[{self,responseStatus}],…}]}}`，不用的字段为 null。排除 isAllDay、freeBusy=FREE、status=cancelled、自己 declined。
- `DingTalkCalendar`（Services）：登录、令牌存钥匙串（`Keychain`）、过期前 2 分钟或 401 时自动续期、每 5 分钟同步；网络出错保留上次日程。纯逻辑在 `Engine/DingTalkProtocol.swift`（PKCE、回调解析、MCP 返回解析、日程提取、查询参数）。权限加了 `network.client` + `network.server`。
- 只调用 `tools/list` 和 `list_calendar_events`，不调用任何会修改日程的工具。
- 2026-10-22 实测：钉钉取消的会议 `status` 为 `cancelled`（标题前的「[已取消]」是钉钉界面加的，不在 summary 里），已正确过滤。设置页「接下来 12 小时有 N 个日程」用 `CalendarEvent.upcomingCount` 只算还没结束、12 小时内开始的（查询范围往前多取了 8 小时，已开完的会以前被误算进来）。

## 设置窗口样式（参考豆包输入法，2026-10-20 改版）
- 无标题栏（`fullSizeContentView` + 透明标题栏），760×600，强制浅色外观。窗口建法见 `SettingsWindowController.makeWindow`（2026-10-23 实测修正）：SwiftUI 视图**外包一层普通 NSView** 再做窗口内容，并用 `setFrame` 设整个窗口 760×600。NSHostingView 直接做内容时会在 600 外再要 32pt 标题栏安全区，窗口被撑到 632、底部白边（关 `sizingOptions`、`safeAreaRegions` 都无效；只在窗口真正显示后才发生，测试必须 `orderFrontRegardless` 再检查）。左侧 212pt 浅灰侧边栏（中下部淡青渐变），右侧 #F7F7F8 背景 + 白色圆角卡片（圆角 14、间距 20、行高 62、卡片内边距 18）。

## 第五阶段：AI 派提醒（v0.5.0，2026-10-24；安装方式 0.7 已改，见第七阶段）
- 文档：设计 `docs/superpowers/specs/2026-10-23-agent-reminders-design.md`、管家场景 `docs/superpowers/specs/2026-10-23-butler-scenarios.md`、第 0 步验证记录 `docs/superpowers/specs/2026-10-23-agent-step0-findings.md`、计划 `docs/superpowers/plans/2026-10-23-agent-reminders-0.5.md`。分支 `feature/agent-reminders`。
- 原则：**歇一会自己不调用任何大模型**。AI（Claude Code / Codex / Claude Desktop）通过 MCP 建、改、查提醒；到点触发只由 App 里写死的代码负责。
- 架构：命令行 target `RestBreakMCP`（产物 `restbreak-mcp`，用 Copy Files 阶段放进 `Contents/MacOS`，单独的权限文件 `RestBreakMCP.entitlements`：沙盒 + App Group）。唯一的第三方依赖是 MCP Swift SDK（0.12.x，只升小版本），只有小程序链接它。
- `Shared/`（主 App、小程序、测试都编译）：`Reminder`（模型）、`ReminderStore`（App Group `B45N72QF4V.com.lizhiming.RestBreak` 下的 `Reminders/store.json`，`flock` 锁 `.lock` 文件 + 原子写 + `schemaVersion`；遇到更新的版本只读不写；写完发 Darwin 通知 `com.lizhiming.RestBreak.reminders.changed`）、`ReminderPlanner`（响铃时间、`due`、`plan`、唯一入口 `process`）、`ScheduleText`（中文描述）、`ReminderTools`（5 个工具，不依赖 SDK）。环境变量 `XIEYIHUI_STORE=test` 改用 `Reminders-test`，端到端测试不碰真实数据。
- 规则：主 App 在下一次响铃等有事的时刻（最晚一小时兜底）在锁里调用 `process`；晚 5 分钟内算准时；晚 5 分钟～12 小时记为错过并汇总一条通知；超过 12 小时只记录；强提醒（firm）在灵动岛上停到被处理，没处理就每 10 分钟再提醒，最多 3 次，第 40 分钟记为错过；灵动岛在休息中、开会、全屏时最多等 30 分钟；接下来 7 天最多 50 条登记成系统定时通知（系统上限 64）；记录保留 90 天；第一次运行不补以前的。
- 限制：最多 100 条有效提醒；`interval` 至少 15 分钟；每个客户端每小时最多新建 20 条；每次最多往后看 400 天。
- 通知：`NotificationRouter` 是唯一的通知代理，只剩提醒的兜底通知（分类以 `reminder.` 开头）。
- 安装（设置「提醒 › 连接 AI」）：Claude Code 用插件（写到 App Group 的 `Integrations/claude-plugin`，复制 `claude plugin marketplace add … && claude plugin install xieyihui@xieyihui-app`）；Codex 复制 TOML 贴到 `~/.codex/config.toml` 末尾（只读工具 `approval_mode = "approve"`）；**不推荐 `codex mcp add`**，它会重写整个 config.toml。Claude Desktop 复制 JSON。
- 坑：同一个 MCP 命令既手动加过、又装了插件时，Claude Code 会把插件里那份当重复去掉；主 App 不能把小程序当子进程启动（沙盒里套沙盒会崩）；小程序找 App 路径要从 `Bundle.main.executableURL` 往上三层（命令行程序的 `bundleURL` 是 `Contents/MacOS`）；Codex 走第三方中转时没有额度数据。
- **提醒的显示：刘海灵动岛**（`UI/NotchIsland.swift`）。2026-10-24 第二版：用户觉得第一版「说不上来哪里不行」，参考 GitHub 高星刘海项目（截图在 `设计/灵动岛参考/`：boring.notch、Atoll、CodeIsland、NotchDrop、DynamicNotch 等）重做，效果图 `设计/提醒样式/E-管家推送-新版.png`。规则：纯黑底；肩部三次曲线的大内凹弧（`NotchShape`）；出场 刘海 → 收起态（刘海左右各 64pt：左图标、右几个字，停 1.6 秒，鼠标移上去立即展开）→ 展开（宽 400，第一行和刘海同高：左来意 + 图标、右时间；然后标题、原因、按钮）；按钮深色平分整行，次按钮深灰白字在左，主按钮在最右，用淡强调色底 + 强调色字（**不要亮色实心按钮**）；强提醒用强调色 1pt 细描边 + 光晕，**不压暗屏幕**；不用图标外的倒计时细环。来意 `IslandIntent`：到点了（普通茶绿 / 强提醒琥珀）、快开始了（天蓝）、可能忘了（茶绿）、该停一停（玫红）、告诉你一声（琥珀）。普通提醒展开 15 秒后收起（鼠标停留不计时）。一次一条排队。没有刘海的屏幕在顶部中间显示同样形状。休息中、开会、全屏时先等，最多 30 分钟。布局坑：黑色形状必须按当前阶段大小画、内容用 overlay 叠上去，收起态内容固定宽度，否则 400 宽的展开内容会把收起态撑宽、圆角和文字被裁掉。
- 系统通知只作兜底：每次响铃登记成系统定时通知，但比响铃晚 90 秒（`ReminderNotifier.fallbackDelay`）；主 App 在运行时会先处理掉这次响铃，重新登记时撤掉它。主 App 按下一次响铃精确唤醒。
- 新建只走 AI，设置页「我的提醒」只能看、暂停、删除，不做手动新建表单（用户明确不要传统规则列表）。

## 第六阶段：管家骨架（v0.6.0，2026-10-26；内置规则和 remember/forget 0.7 已删，见第七阶段）
- 文档：设计 `docs/superpowers/specs/2026-10-24-butler-v2-design.md`（五种来意、感知 → 判断 → 推送、已确认的三项），计划 `docs/superpowers/plans/2026-10-26-butler-0.6.md`。分支 `feature/butler-0.6`。
- 定位：从「到点闹钟」升级为主动开口的管家。**App 仍然不调用大模型**：要「想一想」的事交给用户自己的 AI 定时巡视（约 45 分钟一次，任务说明在 `ButlerPatrol.prompt`，设置「提醒 › 管家」一键复制）。
- 五种来意 `PushIntent`：到点了 / 快来不及了 / 可能忘了 / 该停一停 / 告诉你一声；灵动岛 `IslandIntent(PushIntent)` 配色。
- 推送出口：所有推送（AI 的 `push`、内置规则）写成 `PushRecord`（store 的 `butler.pushes`），状态 pending →（关卡）blocked / waiting →（真正显示时）shown → acted / dismissed / muted；pending 超过 1 小时、或 waiting 因为一直忙等了 30 分钟没显示，记为 expired（写原因）。`PushGate`：「到点了」只去重；其余看屏蔽的来意、同一 `dedupeKey` 一天一次、同一来意 30 分钟一次、每天预算（默认 8，算 waiting 和已显示的，按 `shownAt` 那天算）。小程序 `push` 时就当场过一遍关卡，被拦下直接告诉 AI 原因、不写入；主 App `ButlerCoordinator.processPending` 再过一遍后显示。灵动岛按钮：「少提醒这类」（点一次就屏蔽该来意，设置里可恢复）、「知道了」、主按钮；展开 20 秒自动收起。
- 4 个新工具（`Shared/ButlerTools.swift`）：`get_context`、`push`、`remember`、`forget`；和提醒工具合计 9 个。服务器说明里附上管家说明。
- 现状「要了才写」：小程序 `get_context` 时发 Darwin 通知 `com.lizhiming.RestBreak.context.request`，主 App 收到后才写 `Reminders/context.json`（`BreakCoordinator.butlerContext()`：状态、离开分钟、连续工作、今天首次开工时刻、休息完成/跳过、今天剩下的日程），小程序最多等 1.5 秒；平时不写盘。**context.json 的时间用 `ButlerContext.fileEncoder`（秒带小数）**：ISO 8601 只到整秒，审查发现小程序会把刚写的现状判成旧的、约一半请求失败。
- 内置规则（0.6 只做两条，用户选的）：都由 `BreakCoordinator.tick` 里人在电脑前工作时调 `ButlerCoordinator.userIsActive` 触发，没有单独定时器（改时区、醒来都对，下班那一刻不在也会回来补上）。开工：当天 6 点后第一次在电脑前，一天一次；用钉钉日历时先等今天的日程同步好（最多 10 分钟，`calendarReady`）。收工：下班时间（`butler.prefs.workEnd`，默认 18:30）起 3 小时内第一次在电脑前，一天一次。两条都做完后当天的 tick 直接返回。「今天第一次开始用电脑」存一个键 `butlerFirstActive`（"yyyy-MM-dd HH:mm"）。内容为空时不推。会前 5 分钟、午饭、太晚了暂不做；「AI 等你批准」「AI 跑完没看」在 0.7。
- store 升到 schema 2（`ReminderData.butler`），自写解码兼容 v1。管家设置（预算、屏蔽、下班时间）存在 store 的 `butler.prefs`，小程序也能用。推送记录保留 14 天、过期记事 7 天后清理。
- 设置「提醒」页第三个分段「管家」（`UI/ButlerPage.swift`）：AI 巡视说明复制、每天最多推送、下班时间（`TimeUnit.halfHour`）、已少提醒（全部恢复）、最近推送（没推的写原因）、管家记下的事（可删）。

## 第七阶段：App 只做「嘴」（v0.7.0，2026-10-28）
- 文档：设计 `docs/superpowers/specs/2026-10-28-agent-driven-redesign.md`。分支 `feature/0.7-agent-driven`。
- 用户的定位：用户会用多个 Agent 但主要用一个；歇一会只负责把话递到眼前（灵动岛），**说什么、什么时候说全由用户的 Agent 判断**。接入要标准（MCP），傻瓜操作。明确的到点指令（如 21:00 吃药）留在 App，因为 Agent 的定时任务不保证准点。
- 删掉：内置开工 / 收工规则（`ButlerRules`、`calendarReady`、`DingTalkCalendar.hasFreshData`、`butler.prefs.workEnd`、`TimeUnit.halfHour`）；`remember` / `forget` 和 `butler.notes`（记住用户的事交给 Agent 自己的记忆）；第 0 步留下的 `HookEvent` / `UsageParser`（原 0.7 hooks 感知不做）；`get_overview`（并入 `get_context` 的 `reminders`）；Claude Code 插件和 Claude Desktop JSON 的生成。
- 工具 6 个：`get_context`、`push`（`ButlerTools`）+ `create_reminder`、`list_reminders`、`update_reminder`、`delete_reminder`（`ReminderTools`）。服务器说明写清分工：用户说了明确时间 → `create_reminder`；Agent 自己判断出来、现在值得说 → `push`。
- 关注方向：`FocusPreset`（快开会了 / 答应的事快到期 / AI 任务跑完或在等批准 / 太久太晚 / 开工收工，默认开前三个）+ `butler.prefs.focusCustom`（用户自己写，一行一件，最多 500 字）。`ButlerPrefs.focusForAI` 经 `get_context` 的 `focus` 原样交给 Agent，App 不按它做任何判断；改了不用重新复制任务说明。
- **本机 MCP 地址（2026-10-28，接法参考瑞幸 MCP）**：主 App 在 `http://127.0.0.1:38128/mcp` 提供 MCP（Streamable HTTP，只回 JSON、不开 SSE，GET 回 405），`Authorization: Bearer <密钥>`，密钥存钥匙串（`LocalMCPToken`，设置页可换）。端口被占用时往后找并记在 UserDefaults `localMCPPort`，地址不随重新编译、换安装位置变化。协议部分纯逻辑 `Services/LocalMCP.swift`（`HTTPParser` 支持 Content-Length 和 chunked、`LocalMCPProtocol`：鉴权、Origin 只接受本机、initialize 按客户端版本回、`Mcp-Session-Id` 记客户端名），网络 `Services/LocalMCPServer.swift`（`NWListener` 只绑 127.0.0.1，一次请求一个连接）。工具直接在主 App 里调 `AllTools.call`，现状直接用 `BreakCoordinator.butlerContext()`。**主 App 仍不链接 MCP SDK**。stdio 小程序 `restbreak-mcp` 保留，兼容以前的配置。
- 为什么改：原来给的是小程序路径（stdio），各家 AI 的配置位置和格式都不同、路径随编译变化，AI 接不上（调研见 `docs/superpowers/specs/2026-10-28-mcp-setup-research.md`）。地址 + 密钥是各家都会加的通用写法。用户明确要求**不要扫描用户装了哪些 App**，接入由用户自己的 AI 完成。2026-10-28 实测：Codex（`codex exec` + `url` / `http_headers`）调 `get_context` 成功；Claude Code `claude mcp add --transport http` 显示 Connected。
- 设置「提醒 › 连接 AI」：① 复制接入方式（`AIIntegration.setupText`：通用 JSON 配置 + 免批准工具 + 「新加的 MCP 要新开对话」+ 技能 `AIIntegration.skill`（SKILL.md，含两种开口方式和巡视步骤））② 复制任务说明（`AIIntegration.patrolPrompt`，贴进用户 AI 应用自带的定时任务，**间隔由用户自己设**）③ Codex 手动配置（TOML，`url` + `http_headers`）④ 本机地址 + 「换密钥」。免批准工具 `AIIntegration.autoApprovedTools`（`ToolSpec.autoApprove`）：`get_context`、`push`、`list_reminders`。

  - 「功能接入」`UI/ReminderOverviewPage.swift`：功能说明 + 灵动岛示意 `IslandPreview`（用真的 `IslandView` 展开态画在假桌面上）+ 「下一站：个人健康管家」小标签；「连接只需两步」：① 复制接入指令 ② 复制任务说明（直接展示前 5 行）；连接状态行「更多」展开：每天最多主动推送、已少提醒（全部恢复）、本机地址 + 换密钥、Codex 手动配置。效果图 `设计/提醒样式/F-提醒页介绍.png`。
