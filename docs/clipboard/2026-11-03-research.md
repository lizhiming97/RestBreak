# Maccy 调研与星期五接入建议

日期：2026-11-03。状态：源码调研与候选方案，尚未实施、编译或真机验证。

## 1. 结论

Maccy 是 macOS 剪贴板历史管理器，适合为星期五补齐「以前复制过的东西还能找回来」这一能力。建议抽取并适配它的核心逻辑，做成星期五内置的「剪贴板」模块，统一菜单、快捷键和设置入口。

适配条件较好：Maccy 和星期五都支持 macOS 14+，采用 Swift，界面使用 SwiftUI/AppKit；Maccy 使用 MIT 许可，保留原版权和许可声明后可以修改、合并、分发。不存在因 Maccy 主项目许可而必须拆成独立 App 的要求。

但 Maccy 是完整应用，并非可直接导入的剪贴板 SDK。剪贴板、历史数据、搜索与全局应用状态之间有耦合，不能把几个文件原样拷贝就视作接入完成。

## 2. 调研基线与已确认能力

- 官方仓库：[p0deje/Maccy](https://github.com/p0deje/Maccy)。官网：[maccy.app](https://maccy.app)。
- 本次查询到的最新 Release：[2.8.0](https://github.com/p0deje/Maccy/releases/tag/2.8.0)，发布时间 2026-10-26。
- 源码检查固定于 master 提交 `f0b571e32e4031d7b91ba811f50d0f33e8e5548b`，提交日期 2026-10-26。以下源码结论来自该提交，不将其与 Release 二进制实测等同。

| 能力 | 已核实的实现或行为 |
| --- | --- |
| 保存复制历史 | 监听系统剪贴板变化，支持文本、HTML/RTF、PNG/TIFF、文件 URL |
| 搜索 | 普通匹配、模糊匹配、正则、混合搜索 |
| 图片文字搜索 | 使用本机 Vision 识字，识别结果作为图片条目的可搜索标题 |
| 键盘操作 | 全局快捷键呼出，键盘选取、复制、粘贴、删除 |
| 去除格式 | 将文本以纯文本形式重新写入剪贴板，再按需要粘贴 |
| 常用内容固定 | 固定条目、独立快捷键；清理普通历史时可保留固定项 |
| 本地持久化 | SwiftData，数据库位于应用支持目录下的 `Maccy/Storage.sqlite` |
| 去重与容量管理 | 相似条目合并、复制次数与时间记录、普通历史数量限制；默认数量为 200 |
| 排除记录 | 按应用、剪贴板类型、正则排除；支持暂停及忽略下一次复制 |

文件历史记录的是文件引用，并不等于备份文件内容。原文件移动、删除以及沙盒下的后续访问应单独验证。

## 3. 星期五现在有什么

以下根据本地源码核实，不将本地能力等同于已公开发布的版本：

- 截图完成后可以把图片放入系统剪贴板：`App/ScreenshotController.swift`。
- 「贴剪贴板」可以把当前图片或文字贴到桌面，但没有历史列表：同上及 `UI/PinWindow.swift`。
- 图片识字和翻译已有服务与结果面板；复制原文、译文会写入系统剪贴板：`Services/TextServices.swift`、`UI/TextResultPanel.swift`。
- 已有全局快捷键注册与冲突处理：`Services/HotkeyManager.swift`、`Engine/KeyShortcut.swift`、`Engine/ShortcutConflicts.swift`。
- 菜单和设置分别集中在 `UI/StatusBarController.swift`、`UI/SettingsWindow.swift`。
- 主 App 启用了 App Sandbox；现有功能强调按需加载和低唤醒频率。

因此，本次增量主要是持续采集、历史存储、查找和取用；截图、OCR、翻译、贴图和快捷键基础可以复用。

## 4. 推荐用户体验

用户在网页复制一段资料，又从飞书复制一句话，再用星期五截了一张图。之前的三项内容均可在「剪贴板历史」中找回。

1. 按自定义快捷键，出现小型可搜索面板；也可从星期五菜单打开。
2. 默认按最近复制排序，固定内容在顶部；图片显示缩略图，文本显示摘要。
3. 输入关键词定位内容。普通文本先提供直接匹配；图片 OCR 搜索作为后续增强。
4. 回车将选中内容复制回剪贴板并关闭面板，回到原应用按 `⌘V` 使用。
5. 启用并验证自动粘贴后，提供「复制并粘贴」动作；粘贴目标是呼出面板前的应用。
6. 条目操作可接入「纯文本复制」「固定」「删除」；图片和文本可连接星期五已有的贴图，图片可继续识字与翻译。

剪贴板是用户主动调用的工具，正常复制不弹灵动岛提醒。历史保存在本地；本阶段不扩展 AI/MCP 对完整剪贴板历史的读取能力。

## 5. 接入方式比较

| 方式 | 收益 | 代价 | 建议 |
| --- | --- | --- | --- |
| 抽取核心，内置到星期五 | 一个 App、统一交互；已有截图等能力容易联动 | 需要解除上游全局状态和设置依赖，维护适配层 | 推荐 |
| 独立运行 Maccy，由星期五提供打开入口 | 上游升级容易，初期开发少 | 两个应用、各自设置与历史，功能联动有限 | 适合先试用 |
| 整体搬入 Maccy 应用结构 | 初期能保留较多上游功能 | 菜单、设置、快捷键、启动项、更新器重复，长期维护更重 | 不推荐 |

候选模块边界：

- `ClipboardMonitor`：剪贴板变化检测、排除规则、自己写回内容的标记。
- `ClipboardStore`：历史持久化、去重、固定、容量清理。
- `ClipboardCoordinator`：连接历史面板、原应用焦点恢复和条目动作。
- `ClipboardPanel` / `ClipboardSettingsPage`：星期五自己的界面与设置。

借鉴 `Clipboard.swift` 的多类型数据处理、文件列表写回和排除规则，参考 `HistoryItem`、`History` 的去重与固定逻辑，按需复用搜索实现。Maccy 的 `History` 直接依赖 `AppState`、弹窗、导航、Defaults 等，需要拆开处理。

星期五继续使用已有快捷键和设置基础设施。上游的 Sparkle 更新器、LaunchAtLogin、独立设置框架不应因剪贴板功能而一并引入；若引入 Fuse、Sauce 等第三方代码，再核对各自许可证。

## 6. 两项关键验证

### 6.1 完整历史与低功耗如何兼顾

Maccy 默认每 0.5 秒检查 `NSPasteboard.changeCount`，有变化才读取内容。按持续运行计算，这是每小时约 7200 次检查；该数字不是实际 CPU、系统唤醒次数或耗电测量。

这与星期五现有的「尽量事件驱动、不常驻轮询」方向存在取舍。面向 macOS 14 的完整跨应用采集，不能未经验证就承诺完全事件驱动。只检测 `⌘C` 会漏掉右键复制、应用按钮复制、其他程序写入和通用剪贴板。

建议先做小范围技术验证：

- 功能关闭时停止采集；锁屏、睡眠时停表，恢复后明确采集基线。
- 检查变化与读取/解析内容分开；未变化时不读正文、不解码图片、不写数据库。
- 对图片大小、缓存和历史总容量设边界，界面关闭时释放缩略图和视图。
- 在 Release 版比较关闭/开启功能时的 CPU、唤醒、内存和写盘；再确定采样间隔与空闲策略。
- 降低频率可能漏掉两次采样之间被覆盖的内容，Maccy 的 0.5 秒轮询也不保证捕获任意快速连续复制。需要以实际连续复制流程评估。

### 6.2 复制与直接粘贴分开验证

Maccy 的工程 entitlements 本身也声明了 App Sandbox，不能仅因为星期五有沙盒，就断言必须移除沙盒或另起辅助 App。

可以先闭环「选中历史 → 写回系统剪贴板 → 用户自行粘贴」。自动粘贴则验证辅助功能授权、拒绝后的降级、原应用恢复、中文输入法、全屏、多屏及常用目标应用。当前只核实了上游实现，没有在星期五的签名与运行环境中验证。

## 7. 推荐实施顺序

**第一阶段：日常可用的历史工具。** 文本与图片历史、搜索、固定、删除/清空、纯文本复制、本地保存、数量和容量限制、暂停记录与应用排除，统一菜单和快捷键入口。自动粘贴先做兼容性验证，通过后纳入。

**第二阶段：与星期五现有工具连接。** 历史条目贴到桌面、历史图片识字、识字结果翻译，按需建立图片文字搜索索引。普通图片文字识别在 Maccy 中已有实现，并非星期五独有能力。

**再按实际需要扩展。** 文件复制、多项按顺序粘贴、更高级搜索与条目编辑。云同步和 AI 自动分析不属于本次基础接入范围。

实现时有一处具体联动需要处理：星期五的「复制接入指令」会把含本机 MCP 密钥的配置写入剪贴板。现有复制代码只写 `.string`，新增历史记录前，应为这类内容加不持久化标记，并复用 Maccy 对 concealed/transient 类型的排除逻辑。该规则基于数据标记，不应描述为能自动识别所有密码。

验证重点是实际行为：复制多种内容后可以找回；自己复制历史不会产生重复循环；固定内容与普通历史清理正确；重启保留历史；排除项不入库；存储失败不使休息提醒退出；开启历史后截图、贴图和提醒仍正常。
