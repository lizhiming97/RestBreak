# Mos 滚动核心接入星期五

状态：按用户确认的非商业自用方向实现；独立 worktree、分支、PR，CC review 后合并。与剪贴板 PR 分离，未修改 CC checkout。

## 决策

用户明确授权复用 Mos，在短期不上架、不商业化的前提下保留可剥离边界。本次采用独立 `MouseCompanion/` 进程，主 App 仅提供设置入口与后台启动。另一种整体嵌入完整 Mos 会带入按钮映射、HID 和重复设置，维护范围过大；直接链接进主程序则不适合当前沙盒边界。

复用范围是 Mos 的曲线、滤波、累积与反向重置、轴数据处理及默认参数。星期五封装生命周期、权限与 UI。默认关闭，普通滚轮优先；触控板、连续输入、未知目标、Command/Control 滚动原样通过。用户配置上下/左右反向和平滑、速度与平滑程度，按应用排除。

主 App 不加载 Mos 代码、不改变已有 Bundle ID/App Group/沙盒。鼠标组件独立 Bundle ID `com.lizhiming.FridayMouse`，通过 `friday-mouse://launch|authorize` 拉起。**设置界面在星期五「设置 › 鼠标」页里**（用户要求，不要再做组件自己的窗口）：星期五写 App Group `MouseCompanion/config.json`，组件写回 `status.json`，各发一个 Darwin 通知。主程序里的 `MouseSettings` 与组件的 `ScrollConfiguration` 字段一一对应，两边各有一个测试守住字段名。

## 输入管线

系统滚轮 → event tap → 排除已合成/手势/不适用应用 → 方向变换 → Mos 缓冲与滤波 → CVDisplayLink → 原目标进程。

原事件只有在时钟可用、目标明确、模板可复制后才会抑制被平滑的轴；另一轴照常通过。合成帧打标记避免递归。积压帧不补发，取消代次使旧帧失效；超过 250ms 的帧停顿或 3 秒的输入尾巴丢弃剩余量。应用切换、点击和修饰键变化会刹车；挪动鼠标和停顿后续滚沿用剩余惯性（与 Mos 一致）。

需要真实设备确定的部分是滚轮类型识别、目标 PID 在各应用中的有效性、刷新率差异和最终手感。自动化主要验证数学与事件契约，不能替代这些实测。
