# 菜单栏收纳：设计与接入记录

日期：2026-11-01。分支：`feature/menu-bar-shelf`。基线：本地 `main` 的 `35e507c`（0.7.1 测试包），不是 GitHub 的 0.7.0 快照。

## 范围和决策

用户先确认「图标收纳＋Ice Bar 展开与点击」，随后选定「先做独立 GPL 菜单栏实验版，保留星期五现状」，并进一步要求接入星期五、测试、文档、提交，以及交给 Claude Desktop「桌面时钟」项目复查。

采用独立组件接入：星期五负责入口；GPL 菜单栏组件运行在单独的非沙盒进程。没有更改主 App 的 bundle ID、App Group、钥匙串、MCP、调度规则或沙盒 entitlement。没有直接把 GPL 源码加入主 App 的编译目标。

两种未采用的方案：
- 直接链接 Ice 派生库：技术上可行，但组合版本的 GPL 发布和主进程非沙盒化超出用户选择的独立实验路线。
- 在 MIT 主程序重新实现：不能把复制的实现改标为 MIT；不作为本次交付方式。

首版限定单屏；2026-11-03 起支持多屏，设计见 `2026-11-03-multi-display-design.md`：以每屏分隔符副本为锚点识别本屏图标，在点击的屏幕展开。插拔屏幕、切换桌面或唤醒保持收起，仅在有临时图标待归位时展开。

## 用户路径

星期五菜单「菜单栏收纳…」→ 设置页「打开收纳设置」→ LaunchServices 启动独立组件 → 组件请求自己的辅助功能和屏幕录制权限 → 用户启用 → 将图标移到分隔符左边 → 收起 → 点托盘图标 → 下方横向滚动栏 → 左/右键点击 → 真实图标临时移动并打开原应用菜单 → 菜单关闭后归位。

未安装组件时显示安装/选择说明，不静默下载。首次运行不隐藏图标。每次重新启动组件后需手动启用。退出组件移除占位，星期五提醒继续运行。

## 代码边界

- `RestBreak/RestBreak/UI/MenuBarCompanionPage.swift`：MIT 主程序的启动客户端和设置页。仅发送固定 URL 命令。
- `StatusBarController.swift` / `SettingsWindow.swift`：菜单、导航入口。
- `MenuBarCompanion/`：独立 GPL Swift Package，包括 reusable library `MenuBarShelf` 和 executable `ShelfLab`。
- `IceCore/`：从 Ice 固定提交提取的事件投递、tap、鼠标和超时代码。具体来源和修改见 `MenuBarCompanion/UPSTREAM.md`。
- `scripts/build-menu-bar-experiment.py`：构建两个独立 `.app` 到同一目录；不安装、启动、推送或发布。

组件身份：`com.lizhiming.MenuBarShelfLab`。URL Scheme：`friday-menubar`。命令仅 `settings` / `toggle`。主程序用 `NSWorkspace.open(_:withApplicationAt:configuration:)` 指定经过 bundle ID 检查的组件路径。没有把组件作为继承主程序沙盒的 `Process` 子进程启动。

## 收纳和点击的闭环

1. 分隔符是 NSStatusItem，收起时宽度 10000pt，把左侧项目挤到离屏。
2. 按需获取活动 Space 的菜单栏窗口，捕获各窗口图像，生成代理按钮。
3. NSPanel 放在菜单栏下方，宽度不超过屏幕，内部横向滚动；用 AppKit 处理左右键松手事件。
4. 点击代理前记录真实窗口身份、原右邻居、Space 和原有面板窗口。
5. 根据刘海右边界和左侧应用菜单边界，选择可见插入点。无空间就报错，不盲点屏幕坐标。
6. 使用 Ice 的事件标记、进程 tap / session tap 转发、Command 拖动、鼠标位置恢复和实际位置验证。
7. 临时项存在时每 2 秒检查一次。原应用菜单仍开着则等待，最多 60 次。归位失败（移动超时、鼠标占用、桌面不一致）按 2/4/8/16/30 秒退避重试 5 次。手动“恢复临时图标”不等待面板关闭，直接强制归位。
8. 归位先验证窗口身份，防止窗口 ID 被其他进程复用。原邻居退出则回到分隔符左边。
9. Space 变化不跨桌面自动点击；退出最多等待 10 秒让操作收尾（点击屏障本身有无条件 500ms 超时），然后尝试归位并移除占位；仍未结束则跳过归位，只移除占位。设置页关闭与 App 退出共享同一收尾任务，防止并发移动；收尾期间不能重新启用。

## macOS 26 兼容

状态项可由 Control Center 远端绘制。模型区分绘制 PID 与辅助功能匹配的来源 PID；事件使用来源 PID。虚拟 AppKit windowNumber 不能直接转成 CGWindowID；自己创建的状态项可按唯一 autosave title 定位实际窗口。Preferred Position 以点数保存，分隔符必须位于组件启动图标左侧。

事件适配参考 Ice `macos-26` 固定提交：按移动方向补偿目标坐标，重复 mouse-up 清理按下状态，点击在来源进程与 session 之间建立屏障，并由系统路由实际点击窗口。临时点击验证完整可点击区域，归位验证原右邻居；不能只看到 frame 变化就宣布归位成功。

## 性能

不复制 Ice 的常驻 3 秒图像刷新。没有常驻鼠标移动监听；点击监听仅在浮动条可见时存在。关闭条即释放图像。跨进程枚举只发生在启用、刷新、用户动作、桌面变化和临时归位期间。临时归位检查有总次数限制。事件位置等待每 10ms 挂起，并设置超时，避免原版紧循环。
