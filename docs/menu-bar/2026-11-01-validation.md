## 真机发现及修复

1. **签名证书吊销**：钥匙串同时列出两张同名开发证书，旧脚本选了已吊销的一张。系统日志出现 `CSSMERR_TP_CERT_REVOKED` / `leaf Revocation4`。构建现在逐张执行 `security verify-cert -p codeSign -R ocsp -R require`，选择有效证书并复验成品。没有修改信任或关闭 Gatekeeper。
2. **远端菜单栏渲染**：AppKit 返回 `8589934592` 这样的虚拟窗口编号，直接转 UInt32 会崩溃。改为精确转换，必要时按自己的唯一 autosave title 找实际窗口。单屏取实际 NSScreen，不依赖远端按钮窗口可能为空的 screen。
3. **来源进程不同于绘制进程**：macOS 26 的图标窗口统一归 Control Center。按需用辅助功能位置匹配来源应用，移动/点击发给来源 PID，绘制 PID 仍保留用于窗口身份验证。
4. **拖动与点击协议变化**：参考 Ice `macos-26` 固定提交，加入目标边缘与图标宽度补偿、双抬起、点击进程屏障；点击不设置远端 windowID 私有字段。临时点击前验证整个图标在刘海右侧可点击区域，归位严格检查原邻居顺序。
5. **系统指示灯可插在邻居之间**：临时点击的落点验证与恢复顺序验证分开，避免把隐私指示灯插入误判成“没有移出来”。
6. **Preferred Position 是点数**：不是图标序号。创建分隔符时根据启动图标当前位置设下限，避免重启后把组件自己的启动图标隐藏。
7. **初始布局和浮动栏**：启动时最多四次短重试等待窗口注册；浮动条成为键窗口以接受操作；图标亮度决定背景明暗。无空闲循环截图。

## 开关与跳动修复（2026-11-03）

- 子菜单开关改为自绘（开 = 星期五蓝），系统 NSSwitch 在菜单窗口里始终显示灰色。
- 跳动根因：macOS 26 把拖到屏幕外的图标放在收纳区最左端，不紧挨分隔符；原先按「相邻」验证判失败，每个图标重试最多 5 次（每次含模拟点击与拖动）。收纳/显示改为只验证落在分隔符哪一侧；临时图标归位仍按原邻居严格验证。
- 多屏时主屏第三方图标截不到图（显示虚线方框）：改用另一屏副本截图，仍不行时星期五显示该应用自身图标。实测 17/17 有图。
- macOS 不保存从未被手动拖动过的分隔符位置，重启后收纳选择丢失：组件自行保存分隔符偏移和收起的应用，启动时放回并逐项核对。实测：收起 UU远程 → 一次移动、无重试；重启星期五后仍收起（核对时补了 1 次移动）；放回后无错误。
- 第一次操作无效的根因：macOS 26 同一图标的窗口编号会在两块屏之间互换，星期五按快照里的编号发命令时已过期，组件静默忽略；残留的验证超时也来自同一原因。命令改用稳定标识（应用 bundle ID + 序号），执行时在目标屏重新查找。批量移动中途不再逐个刷新全部应用信息。实测：放出 2 个 0.6 秒、收起 2 个 0.3 秒，无重试；重启星期五后用户的 5 个收起选择自动恢复。
