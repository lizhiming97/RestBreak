# 菜单栏收纳：开关面板与并入星期五的展示

日期：2026-11-03。用户确认：点图标下拉展开、默认不收纳、开关样式；分隔符不可见；并入后菜单栏只保留星期五一个图标，展示要美观和谐。

## 菜单栏上看到什么

| 场景 | 菜单栏 |
|---|---|
| 星期五与组件一起运行（并入后） | 只有星期五图标。组件不创建自己的图标，分隔符不可见 |
| 组件单独运行（没开星期五） | 组件自己的托盘图标（`menubar.rectangle`），点一下展开同一面板 |

分隔符启用期间始终为 10000pt、无文字、无点击动作：收纳靠它挤出左侧图标，它本身就是左侧那段空白。临时图标待归位又遇到换屏/换桌面时缩为 4pt（不可见），让收纳项回到可见区域。不再有「收起 / 展开原菜单栏」状态和 `│`。

首次启用时，分隔符的 Preferred Position 设为「主屏最左侧图标到右边缘的距离 + 10」，保证一开始什么都不收。之后用户的选择随分隔符位置保存，下次启用沿用。

## 入口

- 星期五菜单第一行新增「菜单栏图标…」（图标 `menubar.rectangle`），点后菜单关闭，面板在星期五图标下方弹出。
- 组件没装：打开星期五设置页「菜单栏收纳」。组件装了但没启用或没授权：打开组件设置窗口完成授权和启用。
- 星期五启动时：用户用过一次此入口后，星期五在后台启动组件（`friday-menubar://launch`，不激活）；组件若之前启用过且权限还在就自动启用，否则立即退出。
- 星期五退出：组件随之退出，移除分隔符，全部图标恢复。

组件判断「由星期五托管」：星期五正在运行，且（组件位于某个 `.app/Contents/` 里，或收到过星期五的命令）。星期五没运行时总是显示自己的图标，避免没有入口。

## 面板

位置：触发图标（星期五或组件托盘）在鼠标所在屏幕上那份的正下方，左缘对齐图标，贴屏幕边缘收进。宽 300pt，系统菜单材质（`NSVisualEffectView.menu`），圆角 10，浅/深色跟随菜单栏图标亮度。

```
┌──────────────────────────────────────┐
│ 菜单栏图标                   全部显示 │  13pt 半粗 / 右侧次要按钮
│ ╭──────────────────────────────────╮ │
│ │  [飞书] [WPS] [Cursor]           │ │  已收起的图标，真实图像，点击打开原菜单
│ ╰──────────────────────────────────╯ │  空时：「打开下面的开关，图标会收进这里」
│ ──────────────────────────────────── │
│ [img] 微信                     ( ○)  │  行高 28，图标 18，开关 mini，强调色 #3D7AF7
│ [img] 飞书                     (● )  │
│ [img] 控制中心 · 电池          固定   │  系统固定项与星期五本身：灰色「固定」
│ [img] CC Switch              ◌      │  正在移动：小转圈
└──────────────────────────────────────┘
```

- 一个强调色（星期五设置页的 `#3D7AF7`）只用在开关上；其他全部系统语义色，和系统菜单一致。
- 收起区是面板唯一的「特别」元素：凹陷的浅底槽，图标按真实尺寸排开，超宽时横向滚动。
- 列表按菜单栏从左到右的顺序，最多显示约 12 行，超出滚动。
- 打开开关即收纳，关闭即显示；多个开关排队依次移动。待归位临时图标存在时开关禁用，并在顶部显示「恢复临时图标」。
- 面板在移动过程中不因模拟点击而关闭；点面板外、按 Esc、再次点入口时关闭。关闭即释放图像。

## 影响的文件

- 组件：`ShelfController`（常驻收起、开关队列、面板模型、托管锚点、固定项）、新 `ShelfMenuPanel.swift` 取代 `ShelfPanel.swift`、`SystemBridge`（记录来源 bundle ID）、`ShelfLabApp`（托管模式、命令、自动启用、随星期五退出、设置页改开关）。
- 星期五：`StatusBarController` 菜单第一行、`MenuBarCompanionPage`（命令 `panel` / `launch`、内嵌路径优先、启动时后台拉起）、`RestBreakApp` 启动钩子。
- 打包：`scripts/build-menu-bar-experiment.py` 把组件放入 `星期五.app/Contents/Helpers/` 并按原身份和权限重签主程序。Xcode 直接运行星期五时不内嵌，仍按同目录 / 已注册路径查找。

## 修订：收纳直接放进星期五菜单（2026-11-03，用户确认）

真机试用后用户要求：不弹独立面板，点星期五图标展开的菜单里就能看到并设置收纳；只有首次授权/启用去设置窗口。上文「面板」只保留给组件单独运行时使用。

```
 今天已休息 3 次，完成率 80%
 [飞书] [WPS] [Cursor]           ← 已收起的图标（自定义视图），点击：菜单关闭后临时移出并打开原菜单
 菜单栏图标                    ▸  ← 子菜单：每个图标一行，打勾 = 收起；星期五与系统项带「固定」且不可点
     ...
     ─────
     全部显示 / 收纳设置…
 ─────────────────────────────
```

- 子菜单用系统打勾而不是开关：点击后菜单关闭再移动图标，避免菜单跟踪期间模拟拖动被打断。
- 组件未安装、未授权或未启用：主菜单只显示「菜单栏图标…」，点开引导到设置。

数据流（星期五保持沙盒，只读不枚举）：
- 组件 → 星期五：组件写 `~/Library/Group Containers/B45N72QF4V.com.lizhiming.RestBreak/MenuBarShelf/snapshot.json` 与每个图标的 PNG（按窗口编号命名），然后发 Darwin 通知 `com.lizhiming.RestBreak.menubar.changed`。组件签名加同一 App Group 权限（团队前缀，不触发「访问其他 App 数据」提示）。快照在启用、刷新、每次移动、应用启动/退出、屏幕变化时重写，无轮询。
- 星期五 → 组件：菜单打开时发 Darwin 通知 `com.lizhiming.RestBreak.menubar.request` 请组件刷新；点击时用 LaunchServices 发送 `friday-menubar://hide?id=N`、`show?id=N`、`open?id=N&button=left|right`、`reveal-all`，参数只有数字窗口编号和按键。组件只接受当前主屏图标链里存在的编号。
- 黑白图标（菜单栏常见的单色图标）在快照里标 `template`，星期五按模板图像显示，跟随菜单深浅色；彩色图标保持原色。

名称修复：来源应用名按窗口编号累积保存，某次 AX 查询超时不再把已识别的名称冲成「控制中心 · Item-0」。
