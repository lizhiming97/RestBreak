# 菜单栏收纳：多屏支持设计

日期：2026-11-03。分支：`feature/menu-bar-shelf`（基于 `64fa9d9`）。用户确认：「在哪块屏点，就在哪块屏展开」。

## 背景与实测

用户的机器：内置刘海屏 CG `(0,0,1470,956)`，DELL P2422H CG `(-211,-1080,1920,1080)`（在内置屏上方），「显示器具有单独的空间」关闭。

只读枚举（CGWindowList，状态栏层 25）确认 macOS 26 的行为：

- **每块屏幕各有一份图标窗口**，各自窗口编号不同、都归 Control Center 绘制。两排的顺序相同，整排位置只差两屏右边缘之差（实测 237pt = 1709 − 1472）。
- **同一屏内图标首尾相接**（如 872+34=906、906+35=941），被刘海挡住的项也连续（834+38=872）。
- 内置屏一排 17 项只能看见 12 项；DELL 全部可见。

## 不变的系统限制

收起靠分隔符宽度 10000pt，状态项宽度是全局的：**所有屏幕一起收起、一起展开**，不能只收内置屏。界面和文档如实说明。

## 方案

### 按屏幕识别图标：以分隔符为锚点串链（采用）

每块屏幕上都有一份分隔符 `│` 的窗口。对目标屏幕：

1. 在全部菜单栏窗口里，找标题为 `MenuBarShelfLab.Divider`、`minY` 与该屏 `CGDisplayBounds.minY` 相差 ≤2pt、`maxX` 落在该屏 `[minX, maxX+1]` 内的那份，作为锚点。找不到即报错，不猜。
2. 只看与锚点同一排（`minY` ≤2pt）的窗口。从锚点 `minX` 向左，反复取 `maxX` 与当前边缘相差 ≤2pt 的窗口，得到该屏的收纳链；从锚点 `maxX` 向右同理，得到常显链，不超过屏幕右边缘。
3. 两屏并排且顶边对齐时，两条链右边缘不同，不会接到一起。

未采用：
- 仅按排（`minY`）区分：两屏顶边对齐时混在一起。
- 按 AX 来源匹配副本：依赖每个应用暴露 AX，不可靠。

已知风险：若某个系统元素在链中留出空隙，向外的图标会漏出这一屏的链。表现是该图标不在收纳栏/列表里，不会误操作。需真机观察。

### 目标屏幕

- 托盘左键、`friday-menubar://toggle`：取鼠标所在屏幕（`NSEvent.mouseLocation`），取不到用 `NSScreen.main`，再取第一块。
- 收纳栏只在这块屏幕的菜单栏下展开，锚点 X 取这块屏幕上托盘图标那份的中点。
- 点代理图标时把这块屏幕的 displayID 一并传给控制器；临时移动、点击、归位都只用这块屏幕的链。
- 设置页列表：用主屏（`NSScreen.screens.first`）的链，每个图标只列一次；「收纳 / 常显」移动所有屏一起生效。

### 每屏可点击区域

`leftLimit = max(该屏应用菜单右缘 + 8, 有刘海时刘海右缘 + 20, 该屏 minX)`。若该屏取不到应用菜单（外接屏在「单独空间」关闭时可能没有应用菜单），保守地只用右半屏：`leftLimit = 该屏 midX`。临时项必须完整落在 `[leftLimit, 该屏 maxX]`。

### 移动位置校验

`itemHasCorrectPosition` 从「同一排排序后相邻」改为**几何相邻**：同一排，且 `item.maxX` 与 `target.minX` 相差 ≤2pt（右侧放置时反过来）。只比较同一屏的两份窗口，不受另一屏混排影响。隐私指示灯插在中间时仍判为不相邻，与现有「点击验证可点区、归位验证顺序」的分工一致。

### 桌面（Space）

- 「单独空间」关闭：维持现状，只认当前活动桌面。
- 「单独空间」打开：通过 `CGSCopyManagedDisplaySpaces` 取每块屏幕的当前桌面，接受落在任一屏当前桌面上的菜单栏窗口；归位上下文记录目标屏的当前桌面，只比较这块屏。解析函数为纯函数，单测覆盖；**用户机器为关闭状态，此模式未实测**。

### 环境变化

- 插拔屏幕、切换桌面、唤醒：关闭收纳栏；**不再因屏幕数变化展开**。只有存在待归位临时图标时才展开占位并停止自动归位，等待手动恢复。
- 去掉 `start`、`toggleCollapsed`、`showShelf`、`perform`、`activate`、`restoreIfPossible` 里的单屏判断（共 11 处）。
- 目标屏被拔出时，那块屏上的窗口副本随之消失，无法可靠映射到其他屏：清除待归位记录，图标留在可见区域，提示可在设置列表重新收纳。（实施时修订：原稿为在主屏链上归位。）

### 错误提示

- `unsupportedDisplay` 改为两个明确错误：`dividerMissing`（这块屏幕上找不到收纳分隔符，请稍后重试）与 `spaceChanged`（桌面已切换，请回到原来的桌面）。
- 「单屏实验版」「请断开外接屏」等文字去掉：组件设置页、星期五收纳页（主程序仅改说明文字）、README、设计和验证记录。

## 代码边界

- 新文件 `MenuBarCompanion/Sources/MenuBarShelf/DisplayChain.swift`：纯函数 `dividerCopy(on:in:)`、`chain(anchoredAt:in:displayBounds:)`、`adjacent(left:right:)`、`currentSpaces(from:)`。不依赖 AppKit 状态，单测直接构造窗口数据。
- `SystemBridge.swift`：桌面过滤改用当前桌面集合；新增按 displayID 取当前桌面。
- `ShelfController.swift`：目标屏幕贯穿 `showShelf` → `activate` → `ReturnContext` → 归位。
- `ItemEventDriver.swift`：位置校验改为几何相邻。
- `ShelfLabApp.swift`、`RestBreak/.../MenuBarCompanionPage.swift`：只改文案。

## 测试

自动（组件包内）：
- 上下摆放（用户实际坐标）：两屏各自的收纳链、常显链正确。
- 并排顶边对齐：同一排两条链不串。
- 链遇到空隙停止；隐私指示灯在链中间时仍连续。
- 分隔符副本选择：多份同名时按屏幕选中，找不到返回 nil。
- 几何相邻判定。
- 当前桌面解析：单独空间开/关两种数据。
- 环境变化：仅待归位时展开。

主程序：改文案后重跑 `xcodebuild test`。

真机（用户操作）：
1. 内置屏、DELL 分别点托盘 → 收纳栏在对应屏展开。
2. 两块屏各用左、右键打开一个收纳图标 → 菜单打开，关闭后归位。
3. 设置页收纳 / 常显一个图标 → 两屏同时变化。
4. 收起状态下插拔 DELL → 不展开；插回后两屏都正常。

不覆盖：「单独空间」打开、三屏及以上、竖屏、macOS 14/15。
